# 审核工作台体验收敛回归记录

日期：2026-06-21

## 背景

使用 Halo 缩略图需求任务（4 个类别、41 条用例）按测试工程师日常审核路径检查前端，集中处理误提交风险、审核进度缺失、输入与结果关系不清、诊断信息干扰和需求依据阅读成本。

## 实现结果

1. 类别提交改用独立的类别勾选；行勾选只用于批量修改和标记重复，提交前明确展示类别数与用例总数。
2. 复用 `test_case_feedback` 提供逐条“通过 / 有问题”、已审核与通过/问题计数，并支持审核状态筛选。
3. 生成工作台结果区展示任务输入文档；当前文档选择与任务输入不一致时给出明确提示。
4. 任务详情默认只展示用例审核，技术诊断通过独立视图切换进入。
5. “调试”改为“查看依据”；需求与知识内容优先展示，Agent / Model 信息放入技术详情。Trace API 按知识 ID 补充最多 800 字的正文预览，不修改历史 `source_context`。
6. 用例支持标题、前置条件和步骤关键词搜索；标题固定在左侧，审核操作固定在右侧。
7. 知识库主界面移除有效期、重复、影响任务、来源筛选和后台 job 展示；预览/编辑保留为主操作，重新处理/删除收进“更多”。后端旧数据保持兼容。
8. 文档预览改用 `marked` 的 GFM 解析和 `DOMPurify` 清洗，支持表格、链接、代码及常用行内格式。
