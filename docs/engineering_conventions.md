# 工程约定

本文记录跨需求长期适用的实现与验收约定。待办事项仍写入
[`future_work.md`](future_work.md)，不要混入本文。

## 前端终端范围

- 当前产品按可信本地 Demo 建设，前端只保证常规桌面浏览器宽度下的核心流程可用。
- 窄屏和移动端适配不属于当前实现范围，也不作为功能完成或视觉验收条件。
- 可以保留低成本的自动换行、溢出保护等基础健壮性，但无需为窄屏单独设计布局、交互或测试用例。
- 后续如需支持窄屏或移动端，应先明确目标设备、最小宽度和验收流程，再调整本约定。

## Demo 验证语料

- 产品 Demo 和人工主流程验收固定使用 Halo 缩略图项目：代码仓库为 [`halo-dev/halo`](https://github.com/halo-dev/halo)，产品需求为 Issue [`#2387 希望 Halo 支持附件缩略图功能`](https://github.com/halo-dev/halo/issues/2387)，后端设计为 [`halo-dev/rfcs#24 生成与管理附件缩略图`](https://github.com/halo-dev/rfcs/pull/24)。
- 优先复用 Demo 中已经导入的上述需求和设计文档，重新执行需求分析、审核和用例生成流程，以新生成的任务和诊断数据完成验收。
- `testdata/i1/` 与 `scripts/demo_bootstrap.sh` 提供的是稳定、可重复的仓库内联调 fixture，可用于脚本冒烟，但不能替代 Halo 真实语料的产品 Demo 验收。
- 如需更换产品 Demo 语料，必须先明确新的公开仓库、具体需求和对应设计文档，并同步更新本节；不要在单次待办或回归记录中静默替换。
